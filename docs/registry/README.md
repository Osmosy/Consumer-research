# Реестр требований разбора Inkofood

Реализация гейта реестра требований (`~/projects/vector-grace/registry`) на корпусе этого
репозитория. Реестр — источник истины, `checks.csv` — производный отчёт: гейт перезапускает
проверку, а не читает список.

## Что где лежит

| Файл | Смысл |
|---|---|
| `sources.json` | объявленные источники: протокол и описание разбора (корпус требований), семь колод (корпус доказательств) |
| `spans.jsonl` | спаны по байтовым смещениям: абзацы документов, страницы колод; кэш, пересобирается `parse` |
| `verdicts.jsonl` | вердикт по каждому спану корпуса требований: `background`, `decision`, `constraint`, `requirement` |
| `checkers/check_number_on_page.py` | предикат числовой половины: заявленное число присутствует на цитируемой странице колоды |
| `checkers/check_falsifier.py` + `falsifiers.json` | предикат смысловой половины: перезапуск записанного опровергателя для конкретного утверждения |
| `../requirements-registry.jsonl` | записи требований `REQ-NNNN` (append-only) |
| `evidence.jsonl` | доказательства: `(req_id, перехода)`, `req_hash`, `code_hash`, версия чекера, `defeater`, спан источника |
| `invariants.jsonl` | инвариант `INV-0001` с перечнем 91 перехода (проверка `checks.csv`) |

Колоды объявлены с `"role": "evidence"`: они цитируются страницами, но вердиктов не требуют —
покрытие считается по корпусу требований, а не по источникам доказательств.

## Что зарегистрировано

| Запись | Текст (дословно из спана) | Статус |
|---|---|---|
| `REQ-0001` | «Вердикты: **подтв.** — значение найдено и совпадает; …» — `README.md`, спан 10 | `elicited`, `must` |
| `REQ-0002` | тот же спан, вторая половина определения: «**искаж.** — число есть, смысл другой» | `elicited`, `must` |
| `REQ-0003` | тот же спан, третья: «**подтв.\*** — число верное, но показатель относится к другой категории» | `elicited`, `must` |

Инвариант `INV-0001` проверяет числовую половину: значение найдено. Каждый из 91 перехода —
строка `checks.csv`; доказательство ссылается на спан страницы колоды, на которой стоит число.

Инвариант `INV-0002` проверяет смысловую половину для трёх строк с вердиктом `искаж.`
(24, 25, 87), `INV-0003` — для пяти строк `подтв.*` (10, 73, 17, 18, 75): в `falsifiers.json`
записано конкретное наблюдение, которое опровергает утверждение агента, и приёмка
перезапускает именно его. Это не «модель судит смысл»: опровергатель сформулирован один раз
и с тех пор исполняется.

| Запись | Проверяет |
|---|---|
| `REQ-0001` / `INV-0001` | числовая половина: значение присутствует на цитируемой странице (91 переход) |
| `REQ-0002` / `INV-0002` | смысл для `искаж.`: 24, 25, 87 |
| `REQ-0003` / `INV-0003` | смысл для `подтв.*`: 10, 73, 17, 18, 75 |
| `REQ-0001` / `INV-0004` | строковая проверка: значение стоит в строке того же показателя (87 переходов) |

| Гейт | Результат |
|---|---|
| `coverage` | 28 спанов корпуса требований, все с вердиктом; 260 спанов колод — корпус доказательств, вердиктов не требует |
| `drift` | 0 находок: 186 доказательств, у всех `defeater` и живой спан источника |
| `replay` | 186 из 186 совпадает: 89 `pass` + 2 `fail` числовых, 8 смысловых, 87 строковых |

Оба `fail` записаны честно, а не подогнаны под зелёное: числовой предикат к ним неприменим
(проверка 14 — вычисленное значение, 91 — в строке нет чисел). Приёмка по `REQ-0001`
проходит, потому что проходят 89 доказательств, но два перехода помечены как не прошедшие.

## Строковая проверка: «число есть» → «число в своей строке»

Числовая проверка не отличает верное утверждение от `подтв.*`: число на странице есть, а
показатель не тот. `INV-0004` требует второго: на странице должна найтись строка, где рядом
с числом стоит подпись показателя из `row_labels.json`. Подпись — дословная подстрока строки,
поэтому неверная подпись не проходит: предикат ищет её в тексте страницы.

Подписи черновиком предложил прогон ZCode (батчами по 6, режим `plan`), приняты только те,
на которых предикат вернул `ok`: 87 из 91. Не размечены 4 — 14 (значение вычислено, на странице
его нет), 91 (в строке нет чисел), 25 и 87 (число есть, но смысл проверяется опровергателем,
а не строкой). Второй проход по отклонённым подписям дал +13: причина в первом проходе была
в том, что модель брала подпись с соседней страницы, а не с указанной.

`INV-0004` — не замена смысловой проверке: он ловит «число стоит не в той строке», но не
ловит «строка та, а вывод из неё неверный».

## Смысловая половина: что закрыто и что нет

Восемь вердиктов, которые числовая проверка не различает, получили записанный опровергатель
и перезапускаются `INV-0002` / `INV-0003`:

- 24 — стр. 42: «без нитритной соли» в колонке «Маркетинговый ход» (60,7 / 58,7);
- 25 — стр. 19 ЭКОПСИ: «отличий между поколениями нет»;
- 87 — на цитируемой стр. 16 чисел нет, 58 % живёт на стр. 22 про «курируемые впечатления»;
- 10 и 73 — стр. 22 Nielsen: +19,8 % про ЗОЖ-продукты с протеином, а не про категорию протеина;
- 17 — стр. 4 РОМИР: 36 % на пирамиде с пометкой «Потребительская Панель РОМИР», а не в населении;
- 18 — стр. 68: вещи длительного пользования и дорогие покупки, мебели в перечне нет;
- 75 — заголовок стр. 34 ограничивает «некоторыми топ-категориями по доле СТМ».

Не закрыто: 83 оставшиеся проверки живут только с числовым инвариантом. Опровергатель —
ручная запись, а не понимание смысла: он доказывает ровно то наблюдение, которое в нём
сформулировано, и ничего сверх.

## Корпус доказательств: страницы, которые никто не проверил

260 страниц колод, из них 66 цитируются хоть одной проверкой; 194 не цитируются ни одной.
Из этих 194 у 110 на странице есть числа (то есть там есть что проверять), у остальных —
текст, оглавления, обложки.

Начатая атомизация доведена до конца по всем страницам с числами: 128 страниц разобраны,
112 дали факты (16 оказались без чисел — обложки и оглавления), всего 397 фактов, отклонён 1.
Каждый факт проверен механически: подпись — дословная подстрока строки, число — из той же
строки; непроверенное в файл не попало. Черновик — `page_facts.json` с `deck_sha256` и
провенансом прогона по каждой колоде.

Урок пилота: первая попытка на четырёх страницах дала 2 факта из 16 — модель склеивала
подписи панелей («РБ — 2-3 раза в неделю»), таких подстрок в файле нет, и проверка их
отклонила. После требования «подпись ровно как в строке» — 16 из 16. На всём корпусе это
дало 397 из 398.

Что с этим делать дальше: факты — не требования, а размеченный корпус. Требованием станет
то, что прошло через спаны и получило вердикт; сейчас это материал, по которому можно
проверять полноту — какие факты колод работы моделей не использовали.

## Откуда взялись цитаты для пяти новых опровергателей

Черновик цитат подготовил прогон ZCode CLI (GLM-5.3-Flash, сессия `sess_0394b7f6`,
755 875 токенов из пула Start Plan, режим `plan` — только чтение). Каждая цитата проверена
детерминированно: дословный поиск на цитируемой странице, 5 из 5 найдены. В реестр попали
только проверенные; несовпадение отбрасывалось бы, а не «додумывалось».

## Что гейты ловят на реальных данных (проверено)

- Правка цитируемой страницы колоды без пересборки спанов → `coverage`: `stale_span_cache`.
- После `parse` та же правка → `drift`: `orphaned_source_span` по доказательствам, которые
  ссылались на изменённую страницу (2 записи на РОМИР, стр. 4).
- Подмена предиката или инвариант без переходов → `replay` отказывает с кодом 3.

## Запуск

```bash
python3 ../vector-grace/registry/grace.py --root . parse        # спаны (кэш)
python3 ../vector-grace/registry/grace.py --root . coverage     # покрытие корпуса требований
python3 ../vector-grace/registry/grace.py --root . drift        # три класса дрейфа
python3 ../vector-grace/registry/grace.py --root . replay       # перезапуск 91 проверки, ~5 с
```

Коды выхода: `0` чисто, `1` блокирующие находки, `2` плохой вход, `3` запускать нельзя.

## Чего реестр не даёт

- Смысла сверх записанных опровергателей: их восемь из 91, и каждый доказывает только своё
  наблюдение. Утверждение, для которого опровергатель не сформулирован, смыслом не проверено.
- Полноты против колод: 66 страниц из 260 цитируются хоть одной проверкой, остальные
  доказательствами не покрыты и в реестре не значатся.
- Оценки ошибок предикатов: поля `measured` пусты, набора посаженных дефектов для этого
  корпуса нет; ноль там стоять не должен.
