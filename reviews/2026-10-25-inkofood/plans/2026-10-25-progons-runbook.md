# Что нужно для полноценных прогонов в Vector Marketing

Список собран по факту: один профиль собран, установлен и прогнан четыре раза на числах колод
(персона, архитектура цены, battlecard) — на этом видны все места, где демо превращается в производство.
Порядок — от инфраструктуры к приёмке. Пункты без номера в скобках — то, что уже сделано.

## 0. Что считать полноценным прогоном

Прогон считается рабочим, когда выполнены пять условий:

1. Вход — машиночитаемый факт-лист с адресами `deck=<папка>, page=<N>`, а не пересказ.
2. Агент не добавил ни одного числа, которого нет в факт-листе.
3. Каждое число в выходе сверено с колодой руками, расхождения выписаны.
4. Названы данные, которых не хватает для решения, — списком, а не намёком.
5. Артефакт лежит в репозитории с датой, автором-профилем, стоимостью в токенах и вердиктом сверки.

Всё, что не проходит пункты 1–3, — черновик для внутреннего пользования, а не материал для решений.

## 1. Инфраструктура — один раз

- [x] Собрать дистрибутивы: `python3 scripts/build_profiles.py --clean` → 19 профилей, 146 навыков.
- [ ] Установить минимальный набор: `market-research`, `analytics`, `sales`, `content`, `orchestrator`.
      Остальные 14 — по мере задач; `presentation` и `vk-ads` ставить не нужно (заготовки без навыков).
- [ ] Прописать провайдера **в каждый профиль**: в `~/.hermes/profiles/<agent>/config.yaml` нужен блок
      `providers:` и `model.*`. Без этого падает с «Unknown provider». Один раз сделать шаблон
      `config.yaml.tpl` и раскладывать копией — иначе на каждом профиле одни и те же грабли.
- [ ] Ключи. По манифестам дистрибутивов требуется:
      `DEEPSEEK_API_KEY` — 19 профилей, `HERMES_GATEWAY_TOKEN` — 19 (нужен только для мессенджеров),
      `WORDSTAT_API_KEY` + `WORDSTAT_FOLDER_ID` — 5 профилей (`market-research`, `seo`, `content`, `avito`,
      `yandex-direct`). Без Wordstat `market-sizing` и семантика спроса не работают.
      Опционально: MPSTATS (маркетплейсы), DaData (справочники).
- [ ] Смоук-тест после установки: один вопрос на факт-листе, сверить, что агент не выдумал число.
- [ ] Зафиксировать версию: коммит `vector-marketing`, число профилей и навыков — в шапке журнала прогонов.
      Сейчас это `60288b8`, 19 агентов, 161 навык, 146 в дистрибутивах.

## 2. Контекст клиента — Company Brain

Сейчас это плейсхолдеры по 1,2–7,2 КБ; второй прогон сам сказал: «по Инкофуд контекста нет». Без этого
каждый прогон будет переспрашивать одно и то же. Нужно заполнить восемь файлов:

- [ ] `strategy.md` — миссия, ICP, конкурентное преимущество, каналы. Для Инкофуда: две страны,
      три бренда, каналы «сеть / магазин у дома / рынок», цель на 2027.
- [ ] `offers-positioning.md` — офферы, прайс, УТП. Сюда же — выбранный первым аргумент
      (по нашим данным это «натуральные красители», 65,0 / 76,1%).
- [ ] `brand-voice.md` — голос, запрещённые формулировки. Запрет №1 по данным: «без нитритной соли»
      (60,7 / 58,7% считают маркетингом).
- [ ] `channels-geo.md` — приоритет каналов, гео, GEO. РФ и РБ разводить явно: разрыв по завтраку
      19 п.п., один креатив на две страны не работает.
- [ ] `past-campaigns.md` — что уже пробовали и чем кончилось (сейчас 1,5 КБ пустой структуры).
- [ ] `media-list.md` — медиа и каналы для PR.
- [ ] `legal-compliance.md` — 38-ФЗ, маркировка, ПДн; отдельно допустимость claim'ов «ГОСТ»
      и «натуральные красители» в РФ и РБ.
- [ ] `anti-slop-rules.md` — quality gate. Работает уже сейчас, менять не нужно.

## 3. Данные на вход

- [x] **Факт-лист в машиночитаемом виде.** Собран: `checks/facts.csv` (88 строк), `facts-rejected.csv` (3), `facts-summary.json`; описание колонок — `checks/facts.md`. Из `checks/checks.csv` собран `facts.csv`:
      показатель, значение РФ, значение РБ, `deck`, `page`, вердикт сверки. Сейчас это 91 проверка;
      агент должен получать файл, а не абзац текста.
- [ ] **Бриф на одну страницу**: клиент, бренд, SKU, каналы, бюджет, срок, что решаем.
- [ ] **Список запретов**: утверждения, которые колода не подтверждает (два искажения Грока,
      ярлык «панель» у РОМИР, 58% без адреса). Агент должен видеть их до начала работы.
- [ ] **Полные таблицы с базой и N.** Главный урок прогона battlecard: 2 ошибки из 12 появились там,
      где агент домыслил структуру усечённой таблицы (порог 1,7 / 12,3% вместо 1,0 / 3,5%).
      Правило: если таблица усечена — передавать N, базу, порядок вариантов и явную пометку «список
      неполный», иначе это повторится.
- [ ] **Планы G-01 / G-03** (`plans/2026-10-25-G01-G03.md`) — как вход для research-профиля:
      квота, каналы, дизайн теста. Тогда прогон не переизобретает методику.

## 4. Процесс прогона

- [ ] **Роли и порядок** (проверено, что работает):
      `market-research` → персоны, сегменты, позиционирование, цена;
      `sales` → battlecards и материалы для полки;
      `content` + `creative` + `landing-cro` → сообщения и посадочные под выбранный аргумент;
      `analytics` → план замера, чтобы проверить выбор;
      `orchestrator` → раскладка задачи и сведение. Публикации и бюджеты — только через человека.
- [ ] **Шаблон промпта** — пять блоков, все обязательны: факты с адресами → задача → формат →
      «только на этих числах, без выдуманных цифр» → «перечисли, чего не хватает для решения».
- [ ] **Один прогон — один вопрос.** Персона, цена и battlecard в одном запросе дают кашу; проверено
      на первом прогоне, где пришлось ограничивать «одна персона, 350 слов».
- [ ] **Верификация после каждого прогона**: выписать все числа из ответа, сверить с `facts.csv`
      и колодой, зафиксировать вердикты `подтв. / подтв.* / искаж.`. По факту это 20–40 минут
      на прогон — больше, чем сам прогон (1–2 минуты).
- [ ] **Артефакты**: `runs/<дата>-<тема>-<профиль>.md`, рядом — блок сверки. В шапке: профиль и его
      версия, модель, токены, число вызовов, что было на входе.

## 5. Что починить в самом агентстве

- [ ] `presentation` — заготовка с нулём навыков. Либо вложить навык (у нас есть генератор на
      python-pptx, он сильнее), либо официально не использовать профиль и собирать слайды у себя.
- [ ] `vk-ads` — такая же заготовка, 0 навыков.
- [ ] `timesfm-marketing` лежит в `skills/`, но не вложен ни в один из 19 дистрибутивов. Пока не вложен,
      прогноза сезонности и эффекта промо не будет — G-06 не закрывается.
- [ ] Нет навыка аудита колоды: числа агент берёт из брифа и не сверяет. Достаточно пришить
      `verify_claims.py` как внешний gate: прогон → сверка → вердикт, иначе артефакт не публикуется.
- [ ] Правило «усечённая таблица» стоит внести в `anti-slop-rules.md`: если в брифе таблица без N и базы,
      агент обязан спросить, а не достраивать порог.

## 6. Экономика и режим

| Параметр | Факт по прогонам |
|---|---|
| Токенов на прогон | 54 021 (цена), 73 504 (персона), 136 005 (battlecard) |
| Вызовов API | 3 / 4 / 6 |
| Время прогона | 1–2 минуты |
| Время сверки человеком | 20–40 минут |
| Цена | отчёт показывает `estimated_cost_usd: 0.0` — считать по своему тарифу токенов |

- [ ] Решить частоту: разовые прогоны под задачу — дёшево и полезно; еженедельный мониторинг
      конкурентов — только после того, как заполнен Company Brain и есть цены/полка конкурентов.
- [ ] Бюджет на квартал считать из «токенов на прогон × число прогонов + сверка», а не из подписки.

## 7. Чего делать не нужно

- Не поручать агенту проверку чисел: в агентстве нет навыка аудита колоды, и он этого не умеет.
- Не ждать экономики (G-02) без себестоимости, наценки канала и цен полки — оба прогона честно
  отказались считать маржу и перечислили, что нужно.
- Не ставить агента на публикацию и бюджеты: в `workflows/handoff-protocol.md` человек подтверждает
  всё внешнее — это правильная граница, оставить как есть.
- Не гонять один запрос «сделай стратегию»: разбивка на один вопрос на прогон даёт проверяемый выход.
