# Чистка легенды вердиктов: пробный прогон

Дата: 2026-11-02. Прогон на копии проекта (`/tmp/legend-dryrun`), настоящий реестр не тронут.

## Зачем

REQ-0001…REQ-0003 — строки легенды вердиктов («подтв.», «подтв.\*», «искаж.», «не подтв.»).
Содержательно это определения, но в реестре они живут как требования с доказательствами,
поэтому «доказано 30 из 43» включает три строки, которые ничего не обещают продукту.
Содержательное число — 27 из 40.

## Что сделано на копии

```bash
cp -r consumer-research /tmp/legend-dryrun
python3 registry/grace.py --root /tmp/legend-dryrun revise --req REQ-0001 --status rejected ...
# то же для REQ-0002, REQ-0003
python3 registry/grace.py --root /tmp/legend-dryrun drift|coverage|replay|status
```

## Результат

| гейт | значение на копии |
|---|---|
| drift | БЛОК: 220 блокирующих |
| в том числе `orphaned_evidence` | **204** |
| в том числе `orphaned_reference` | 3 (ссылки из `docs/facts/config.json`) |
| в том числе `unproven_requirement` | 13 (не изменилось) |
| coverage | ЧИСТО |
| replay | проходит, все записи совпадают |
| требований живых | 40 вместо 43 |
| доказательств | 479 записей, из них 204 указывают на мёртвое требование |

## Вывод

Простое отклонение легенды **не проходит**: 204 записи доказательств остаются без живого
требования, и drift даёт 220 блокирующих вместо 13. Значит, чистка — это не смена статуса,
а переписывание журнала доказательств: удалить или переназначить 204 записи, снять 21 инвариант,
убрать три ссылки из конфига и проверить, что остальные обязательства не потеряли доказательств.

## Решение

Не применять. Настоящий реестр оставлен как есть; долг записан числами в кейсе §7.
Условие применения из плана (replay совпадает **и** `orphaned_evidence` = 0) не выполнено.

Что понадобится для следующей попытки: вынести легенду из реестра как данные (файл определений
вместо требований), а не переносить её статусом; тогда доказательства на неё не ссылаются вовсе.
