# Разбор работ трёх моделей по колоде «Инкофуд»

Три агента независимо разобрали одну и ту же колоду — `decks/inkofood-2026` («Инкофуд. Исследование
потребителя», октябрь 2026, 69 слайдов, n=900: РФ 600, РБ 300) и сопоставили её с шестью остальными
колодами репозитория. Здесь лежат их работы без изменений, сводная презентация по ним и пояснение,
где у каждого слайда указан источник.

Дата разбора: 25 октября 2026. Колода: [`decks/inkofood-2026`](../../decks/inkofood-2026).

## Как проверялись работы

Один перечень на все артефакты каждой работы: спецификация (md), презентация (pptx), у Гемини ещё и PDF.
Числа, которые есть только на слайдах, в спецификацию не попадают — именно там нашлись самые вольные
значения («92% мяса», «окно ≥60% площади», «1–20%+»).

| Агент | Проверок | Подтверждено | Искажено | Нет в колоде |
|---|---|---|---|---|
| Agent 1 · Клод | 17 | 17 | 0 | 0 |
| Agent 2 · Грок | 7 | 5 | 2 | 0 |
| Agent 3 · Гемини | 78 | 44 | 6 | 28 |
| **Итого** | **102** | **66** | **8** | **28** |

Вердикты: **подтв.** — значение найдено и совпадает; **подтв.\*** — число верное, но показатель относится
к другой категории; **искаж.** — число есть, смысл другой; **не подтв.** — значения нет ни на одном
слайде колоды (ни в таблицах, ни в подписях, ни в примечаниях).

Счёт по блокам важнее общего: провал у Гемини локализован. В поведении — 11 из 11, в продукте — 19 из 27;
в демографии — 0 из 7, в поколениях — 1 из 5, в макро — 7 из 20 при 11 отсутствующих значениях.

## Как воспроизвести

```bash
# перечень проверок и статистика
python3 checks/verify_claims.py

# аудит чисел самой сводной презентации против data/values.csv
python3 checks/audit_deck_numbers.py     # нужен python-pptx
```

`verify_claims.py` — единственный источник чисел в презентации и в пояснении: счёт по блокам
и приложение A печатаются из него, поэтому они не расходятся между версиями документа.

## Оговорки

- Работы агентов включены как есть, включая ошибки — в этом и смысл разбора. Ничего в них не правилось.
- Файлы сняты с сохранением времени файла, sha256 каждого — в `MANIFEST.json`.
- Числа колоды цитируются как `deck=<slug>, page=<N>`, где `N` — номер слайда в `deck.json`.
  Это не всегда номер, который называет агент: у Гемини ссылки на слайды местами сдвинуты, поэтому
  сверка шла по содержанию слайда, а не по номеру.
- `data/values.csv` не содержит всего: по слайду 50 (знание и покупка брендов) в CSV есть только ряд
  «Знаю». Ряд «Покупаю» — в `decks/inkofood-2026/inkofood-2026.md`, таблица из двух рядов.
  Поэтому воронку брендов нужно сверять по `.md`, а не по CSV.
